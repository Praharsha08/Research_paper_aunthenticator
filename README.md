# Research Paper Quality Analyzer & Score Predictor

An ML-powered software system that evaluates the quality of research papers. The system leverages LightGBM regressor ensembles, dense SentenceTransformer text embeddings, and SHAP explainability to predict quality scores and provide local feature attributions.

![System Architecture](docs/architecture.png)

---

## 📌 Problem Statement
For academic recruiters, journal editors, and researchers, evaluating the quality, novelty, and rigor of a research paper is time-consuming and subjective. 
This project builds a **data-driven scoring pipeline** to:
1.  Quantify a paper's overall quality and sub-score metrics (Novelty, Rigor, Impact).
2.  Provide transparent explainability maps detailing *why* the model assigned a score.
3.  Recommend semantically similar publications from the dataset to contextualize performance.

---

## 🛠️ System Architecture & Workflow

The data flow within the application follows a modular architecture:

1.  **PDF Parsing:** Extracts text page-by-page from raw uploaded document streams using PyMuPDF (`fitz`).
2.  **Abstract Segmentation:** Isolates the text within the `Abstract` boundaries using heuristic structure scanning.
3.  **Semantic Vectorization:** Embeds the segmented abstract into a dense 384-dimensional vector space using the `all-MiniLM-L6-v2` SentenceTransformer.
4.  **Metadata Preprocessing:** Cleans and formats scalars (author counts, character lengths) and aligns categorical codes (`primary_category`).
5.  **Multi-Model Regression Ensemble:** Runs the preprocessed features through 4 separate LightGBM regressor models.
6.  **Local XAI Analysis:** Computes local feature contributions using TreeSHAP, aggregating high-dimensional vector impacts into a single semantic attribute.
7.  **Semantic Recommendation Search:** Conducts a brute-force cosine similarity nearest-neighbor sweep against a local 181-paper database to display the top 3 similar works.

## 📊 Dataset & Feature Engineering

### **Dataset Description**
The training corpus contains metadata and full-text extractions for **181 research papers** from ArXiv, covering categories such as Machine Learning (`cs.LG`), Computer Vision (`cs.CV`), Computation and Language (`cs.CL`), and Neural and Evolutionary Computing (`cs.NE`). The current dataset contains 115 records with all score targets set to zero. An audit found that every one also has zero novelty, rigor, and impact scores, while the 66 scored records range from 58 to 94 overall. The pipeline therefore preserves these records in the raw dataset but excludes them from model training and evaluation as unlabeled placeholders.

### **Feature Vector Construction ($D = 389$)**
*   **Scalars ($D=4$):**
    *   `author_count`: Number of authors.
    *   `summary_len`: Character length of the abstract.
    *   `text_len`: Character length of the full paper.
    *   `years_since_published`: Paper age in years calculated dynamically from current system time.
*   **Categorical ($D=1$):**
    *   `primary_category`: The primary ArXiv category aligned using Categorical codes.
*   **Semantic Embeddings ($D=384$):**
    *   `emb_0` to `emb_383`: Dense sentence embeddings representing the abstract's semantic structure.

## 📈 Model Performance & Metrics
`inferencetest.py` reports leakage-safe **5-fold out-of-fold metrics**: every prediction is generated by a model that did not train on that paper. These should replace the previous same-data evaluation figures. On the current dataset, the out-of-fold results are:

| Metric | Overall Quality Score | Novelty Sub-Score | Rigor Sub-Score | Impact Sub-Score |
| :--- | :---: | :---: | :---: | :---: |
| **Mean Absolute Error (MAE)** | **6.168** | 2.636 | 1.944 | 2.673 |
| **Root Mean Squared Error (RMSE)** | **8.349** | 3.541 | 2.455 | 3.665 |
| **R² Score (Variance Explained)** | **-0.118** | -0.336 | 0.116 | -0.252 |
| **Predictions Within $\pm 5$ Points** | **53.0%** | 89.4% | 95.5% | 87.9% |
| **Predictions Within $\pm 10$ Points** | **81.8%** | 98.5% | 100.0% | 97.0% |

These metrics use the 66 records with non-zero labels. The 115 all-zero records are excluded as unlabeled placeholders and should be rescored before being added to future training runs.

## 🔍 Explainability & SHAP
To ensure predictions are not a "black box," the system integrates TreeSHAP:
*   **Local Contribution:** Calculates how much each feature pushed the prediction away from the dataset expected base value.
*   **Embedding Aggregation:** Sums the SHAP values of the 384 embedding columns into a single attribute: `Text Semantics (Embeddings)`. This allows the user to see the cumulative impact of the abstract's vocabulary on the final score.

## 🖥️ Usage Instructions

### **1. Run Model Training**
Retrains all 4 models on the full dataset and exports serialized joblib binaries to `models/`:
```bash
python train.py
```

### **Manual Dataset Annotation**
Use the Streamlit sidebar's **Annotate dataset** mode to score currently
unlabeled papers. Each paper receives 1–5 ratings for overall quality, novelty,
rigor, and impact, with optional notes. Annotations are stored separately in
`data/annotations.json`; the raw JSON datasets are never modified. After enough
papers have been reviewed, a conversion step should map these ratings into the
model's existing target ranges before retraining.

To validate and import saved annotations:

```bash
python scripts/import_annotations.py
```

This creates `data/annotated_embeddingdataset.json` without modifying the raw
dataset. Existing non-zero labels cannot be overwritten, unknown ArXiv IDs are
rejected, and all four 1–5 scores are required. Once the enriched file exists,
`train.py` uses it automatically; otherwise it continues using
`data/embeddingdataset.json`.

### **2. Run CLI Evaluation & Validation**
Evaluates global performance metrics, prints category breakdowns, and runs a terminal-based ASCII SHAP explainability plot for a sample record:
```bash
python inferencetest.py
```

### **3. Start Streamlit Dashboard**
Launches the interactive Web UI:
```bash
streamlit run app.py
```

## ☁️ Deploy on Streamlit Community Cloud

1. Push this repository to GitHub, including:
   - `app.py`
   - `src/`
   - `data/embeddingdataset.json`
   - `models/`
   - `requirements.txt`
   - `runtime.txt`
2. Open [Streamlit Community Cloud](https://share.streamlit.io/) and sign in with GitHub.
3. Select **Create app**.
4. Choose repository `Praharsha08/Student-project`.
5. Select the `main` branch.
6. Set the main file path to `app.py`.
7. Click **Deploy**.

The first deployment downloads the `all-MiniLM-L6-v2` embedding model, so startup
may take several minutes. The application needs the model binaries and embedded
dataset in the repository; do not remove the `models/` or `data/` directories.

The annotation screen writes `data/annotations.json`. Streamlit Community Cloud
instances should not be treated as permanent storage, so export or commit
annotations separately before restarting or redeploying the app. The current
production scoring workflow is the **Analyze paper** mode; **Annotate dataset**
is a data-collection utility.
